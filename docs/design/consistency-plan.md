## 1. The design system as it exists

Tokens live in `src/app/design-tokens.css` (light `:root`, dark `.dark` on `<html>`; there is no `prefers-color-scheme` rule, which is deliberate: Light is the default regardless of OS, per CLAUDE.md). Defined: colours (surface, text, border, primary, success, warning, danger, info with `-soft` backgrounds and `-text` foregrounds), `--radius-sm 8 / md 12 / lg 14 / xl 18 / pill`, `--space-1…12` (4 to 48), `--font-ui`, `--font-display`, shadows, motion. All component styling is in `src/app/globals.css` (1 934 lines, 138 class rules, sectioned by work item). Shared components: `Button` (`src/components/ui/button.tsx`, adds `.button`, disables and shows a spinner while the form is pending), `ActionForm` (feedback, pending state, preview/confirm, undo), `Disclosure` / `DisclosureTabs` (in-place panels), `ResourceLink`, `CategoryIcon`, `DateJump`, `PageShortcuts`, `BrandMark`. Icons are lucide-react.

**Reference screens.** Today (`src/app/today/page.tsx`) and Weekly review (`src/app/review/page.tsx`) are the best-designed: eyebrow → `page-head` with one primary action → live hero or stepper → cards with `h2`, tabular numbers, quiet status tones, consistent 13 px muted meta. The application page (`src/app/jobs/[id]/page.tsx`) is the best detail page: one summary line, facts as a `dl.job-facts`, flat sections for lists. Roadmap and Practice should read like those three.

## 4. Canonical set

**Tokens to add** (`design-tokens.css`, both themes where relevant):
`--text-xs: 11px` (eyebrow, pill), `--text-sm: 13px` (meta, buttons, links), `--text-md: 15px` (body, item titles), `--text-lg: 19px` (h2), `--text-xl: 25px` (hero h2), `--text-2xl: 36px` (h1); `--radius-xs: 6px` (pill, kbd, week block), `--radius-control: 10px` (buttons, inputs, nav links; keeps today's look rather than moving everything to 12); `--tap-target: 44px`; `--font-mono`; `--overlay: rgb(27 26 22 / 35%)` with a dark value; `--bp-phone: 700px`, `--bp-tablet: 1050px` (as documented constants; CSS media queries cannot read custom properties, so these stay literal but centralised in one comment block). Spacing already has every step needed: the 76 off-scale values map to the nearest token (13→12, 15→16, 22→24, 23→24, 34→32, 35→32, 25→24, 7→8, 5→4, 9→8).

**Buttons.** Canonical: the shared `Button` for every submit button inside an `ActionForm` (it owns pending and busy state); raw `<button className="button">` only for `type="button"` client controls. Hierarchy per view: exactly one primary (`.button`), everything else `.button.secondary`, and `.button.destructive` for Remove / Disconnect / Sign out (the class exists; apply it). Navigation is `.link`; in-place toggles are `Disclosure`. Chevron buttons keep `aria-label`.

**Inputs.** Canonical form wrapper `.form` (alias `.dsa-form` kept during migration, removed at the end) on every `ActionForm`; `.form-grid` for two columns; `label.check` for checkboxes; `.filters` (alias `.dsa-filters`) for GET filter rows. Optional fields say "(optional)" in the label; required ones carry `required`. Validation on submit (ActionForm already preserves input on error).

**Modals.** None. Disclosure for in-place forms; the shortcuts overlay is the only dialog and gets `aria-modal` and a focus return to its trigger.

**Cards.** `.card` for things that act (forms, live blocks, heroes), `.card.flat` for lists on the canvas, `.setup-card` for first-run, `.today-focus` for the stat hero. Every `section.card` gets `aria-labelledby` or `aria-label`.

**Lists.** One `.list-row` rule (grid: body, meta, actions; hairline between rows; density 12 px / 0) replaces `.dsa-item`, `.routine-row`, `.goal-row`, `.prep-item`, `.note-row`, `.learning-history` over the batches, keeping the old names as aliases until the last batch. Numbers and dates right-aligned with `tabular-nums` in a `.list-meta` column; long titles truncate with `title=` for the tooltip. Sticky sub-header (filters) for lists above about 40 rows.

**Badges.** `.pill` with semantic tones only: `success`, `warning`, `danger`, `info`, `neutral` (aliases `green`, `yellow`, `red` kept one batch). Tone mapping: done/completed/asked → success; due today/skipped/needs attention → warning; overdue/error/RED → danger; in progress/current/question → info; P0 keeps `priority` (brand teal) because it is emphasis, not status.

**Feedback.** ActionForm only. `role=alert` + `.form-message` for errors; `role=status` + `.form-success` for success; warnings that are not form results (calendar attention) get a `.notice.warning` class instead of borrowing `.form-message`.

**Page headers.** Every page: `p.eyebrow` → `div.page-head` (`h1` + at most one primary action). Detail pages keep the back link above the eyebrow and adopt `page-head` (problem, topic, application, settings). Review keeps its serif heading as the one editorial exception.

**Empty states.** First run → `.setup-card`; an empty list inside a section → one `p.muted` line with the next action as a `.link`; retire `.empty` (dashed box) and the whole-card variant.

**Icons.** lucide only, 16 px in rows and buttons, 18 px in navigation, 14 px inside pills and feedback; the unicode marks become `Circle`, `CircleDot`, `CircleCheck` (roadmap status), `ExternalLink` (ResourceLink), `ChevronLeft`/`ArrowLeft` for back links; `→` in link text stays (it is copy, not an icon).

### Friction found

1. **Weight.** A 304-item roadmap is one page (2.8 MB after the fix) with no per-section collapse; Continue jumps by anchor but the whole page loads first. Sections with 20–30 problems each push the next pattern below the fold.
2. **Duplicate affordances** on the overview: title link and an "Open" button do the same thing; "Edit" per goal row.
3. **Overview section list** is 31 entries long for the behavioural roadmap; scannable but not useful at that length.
4. **Study panel** defaults the scenario to the first one every time; "Copied" says nothing about what to do next; problem items show "Record an attempt" outside the panel, not beside the prompt.
5. **Notes are buried**: the one field the owner edits daily sits 13th in the Edit form, below source material that never changes for imported items (scope, checkpoint, references).
6. **Two marks for one problem**: Done on the roadmap and Record an attempt in Practice are separate; the attempt needs two required selects whose values are coupled by a rule ("solved on your own needs Yellow or Green"), so the second select is mostly inferable from the first.
7. **Dead end after an attempt**: the problem page's back link goes to `/dsa`; there is no way back to the roadmap item, and no "what's next" after saving (next due problem, or the roadmap).
8. **Filters need Apply** and a reload; the roadmap's filter state is kept in the URL (good) but Practice's "Clear" link drops the `#library` anchor on some paths.
9. **Practice is organised for the pre-import world**: "Current topic / Next up in Arrays" shows a seed topic with nothing in it while the imported pattern topics hold the problems; making a topic current costs three clicks through a five-field form; "Add a problem" is the primary action although problems now arrive from the roadmap.
10. **Keyboard**: Enter submits (native), `?` opens shortcuts, Esc closes the overlay and the phone sheet, but Esc does not close an open Disclosure panel and focus does not return to the trigger; Copy prompt has no key.
11. **Reopen** clears the revision schedule with no Undo (Remove has one).
12. Inline validation happens on submit only (fine), input is preserved on error (ActionForm keeps the fieldset), success feedback exists; nothing to fix there.
