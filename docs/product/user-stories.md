# Product scope and user stories

## Product intent

As a working software engineer, I want a flexible daily execution system so I can spend less time deciding what to do and see what actually happened. CareerOS supports interview preparation, job search, fitness and arbitrary personal goals. It must not hard-code one language exam or career path.

Current persona: one private workspace owner. Future employees maintaining the product are contributors, not another product tenant. Multi-user accounts, calendar sync, AI planning, job scraping and closed-app push are not delivered features.

## Story template and definition of done

Use the GitHub user-story template. Record persona/outcome, scope exclusions, Given/When/Then criteria, edge cases, relevant NFR IDs, migrations, dependencies, and test plan. The PR names the story IDs, explains behavior, updates docs, and supplies validation evidence. “Done” requires reviewed implementation and passing relevant checks, not merely code merged. No performance/security claim is complete without its specified evidence.
