# WI-008.1 handoff — Heroku container deployment path

Branch `feat/wi-008-1-heroku-container` on `main` at `a670dab` (PR #8, brand system). Verified 2026-09-26 on disposable local databases. No personal data was involved: the local `.env` database was confirmed to hold only the example seed, and one safety backup of it was taken with `pnpm db:backup` before any change.

## 1. Outcome

Silsila has a decided, documented and rehearsable hosting path: **Heroku container stack** (Eco dyno + Postgres Essential-0, funded by the GitHub Student Developer Pack credit for 24 months), recorded in [ADR-013](architecture/decisions.md#adr-013--heroku-container-hosting-with-portable-12-factor-constraints). The repository now builds a portable production image and applies database TLS through one explicit setting. The Heroku app itself, DNS, the real Google client and real-device push are owner-run follow-ups listed in section 8. No product feature was added; the feature freeze stands.

## 2. Decision summary

Free tiers reviewed on 2026-09-26 and why they lost: Render free web sleeps after 15 idle minutes (the per-minute reminder job would keep it awake) but Render free PostgreSQL expires after 30 days; Neon free caps compute at 100 CU-hours per month and suspends past it, which a per-minute job exceeds; Koyeb free PostgreSQL allows 5 hours per month; Fly.io and Railway have no free tier; DigitalOcean's student credit ended August 2026; AWS's free tier became six-month credits; Oracle's Always Free VM is capable but self-managed. Heroku Eco sleeps after 30 idle minutes, the cron keeps it awake, and 1000 Eco hours cover a month of web time plus one-off dynos. After the credit: about $10 per month.

Portability rules that keep a later move to DigitalOcean, Fly, AWS or a VM a redeploy plus restore: configuration only from environment variables, plain PostgreSQL by URL, scheduling as an authenticated HTTP call, one stateless process, `pg_dump` backups, and one Dockerfile as the deployment artifact.

## 3. Image and compose

- `Dockerfile`: multi-stage (`base` → `deps` → `build` → `runtime`) on `node:24-bookworm-slim` with pnpm pinned to the `packageManager` version, plus `openssl` and `ca-certificates` (the Prisma migration engine links against OpenSSL and outbound TLS needs CA roots; the first build without them warned). The build stage drops `.next/cache` (about 180 MB of webpack cache that only speeds up the next build). The runtime stage installs production dependencies only, removes the pnpm store afterwards, copies `.next`, `public`, `src`, `prisma`, `scripts` and the three config files, regenerates the Prisma client, and runs as the unprivileged `node` user with `pnpm start` on `PORT`. Each stage is commented as a learning reference.
- `.dockerignore` keeps `node_modules`, `.next`, `.git`, every `.env*` except the examples, backups, docs and tests out of the build context.
- `heroku.yml` declares the Dockerfile as the `web` process. No release phase: migrations stay owner-run after a backup.
- `compose.yaml`: the database host port is `${DB_PORT:-5432}` so the container can coexist with a local PostgreSQL; a new `app` service under `profiles: [app]` builds the image, reads `.env.docker` (git-ignored; template `.env.docker.example`) and depends on a healthy database. `docker compose up -d db` is unchanged.
- `prisma` and `tsx` moved from devDependencies to dependencies so `pnpm db:deploy` and `pnpm timestamps:audit` work from the image. Lockfile refreshed; no version changes.

## 4. Database TLS (`DATABASE_SSL`)

`pg-connection-string` 2.14 treats `sslmode=require` as full verification and Heroku injects a `DATABASE_URL` without SSL parameters, so TLS is now an explicit setting: `DATABASE_SSL=off|no-verify|verify-full` with optional `DATABASE_SSL_CA`. `src/lib/database-ssl.ts` parses it (names only in errors) and produces the node-postgres `ssl` option; `src/lib/database.ts` applies it to `createPgAdapter` and builds the Prisma CLI URL (`sslmode=require&sslaccept=accept_invalid_certs` or `sslmode=verify-full[&sslcert=…]`). Consumers: the application pool and the raw start-up time-zone check (`src/server/db.ts`), `prisma.config.ts`, and the timestamp audit/repair clients. `src/lib/env.ts` validates the values and rejects a CA path outside `verify-full`. `off` keeps any `sslmode` in the URL in charge, so local and CI behaviour is unchanged.

## 5. CI

`.github/workflows/quality.yml` gains an `image` job that runs in parallel with `quality`: it builds the runtime image and starts it with no configuration, asserting exit code 1 and that the output names `DATABASE_URL`. Nothing is pushed to a registry.

## 9. Rehearsal results and known limitations

Docker Desktop 29.8 / Compose 5.5 on Apple silicon, 2026-09-26, `DB_PORT=5433 docker compose --profile app up --build` against the bundled PostgreSQL 17:

- Image: 1.1 GB on disk (`docker image ls` reports 1.42 GB because it counts hard links twice); `node_modules` 741 MB, of which about 230 MB is the Prisma CLI and its dependencies, and the built `.next` output is 7 MB. Heroku builds the amd64 variant. Shipping migrations from a workstation instead of the image would save that 230 MB; not done, because `heroku run pnpm db:deploy` is the simpler operating procedure.
- Start-up: configuration accepted, no warnings. `pnpm db:deploy` inside the container applied all 10 migrations (proves the CLI and OpenSSL work in the image).
- HTTP: `/api/health` → `{"status":"ok","database":"ok","sessionTimeZone":"UTC","schema":"current"}`; `/today` → 307 to `/login?next=%2Ftoday` with HSTS, nosniff, `X-Frame-Options: DENY`, referrer and permissions policies; `/login` 200; cron POST without bearer 401, with bearer 200 and a zero-count summary; `/api/export` 401; manifest, service worker and SVG favicon served with correct types.
- No configuration (`docker run --rm -e NODE_ENV=production`): exit code 1, output lists variable names only. This is what the CI `image` job asserts.
- `DATABASE_SSL=no-verify` against the plain-TCP database: start-up logs `Error opening a TLS connection: The server does not support SSL connections` (no credentials in the log) and `/api/health` returns 503 `degraded`, so a wrong TLS setting is visible immediately.
- Found and fixed during the rehearsal: the start-up server-default check treated the Docker image's `Etc/UTC` as a non-UTC zone and printed the legacy-repair warning. `isUtcZone()` now accepts PostgreSQL's spellings of UTC (unit-tested); the session pin itself was already correct.

Not rehearsed locally: Google sign-in (needs HTTPS and a real client), push delivery, and `verify-full` against Heroku's certificate chain.

Limitations: `verify-full` against Heroku's certificate chain is untested until the database exists. Essential-0 has manual backups only and no point-in-time recovery. The dyno restarts daily, resetting in-memory rate limits. The Dockerfile must be updated if a new file is read at start-up by Next.js or Prisma. Release-phase migrations are deferred until a backup schedule exists.
