## Release decision

The code is a verified single-owner development baseline, **not yet certified production-ready**. Before an internet deployment with real personal data, the maintainer must resolve NFR-002/003/004/012, establish scheduler operations, and record the remaining target decisions and accepted limitations. Before a public multi-user product, US-026 is a separate architecture/security work item.

For each gate, record owner, environment, date, command/run link, result, residual risk and sign-off in the release PR. Do not change an Open/Partial status to Verified based only on documentation. Product feature completion and operational readiness are tracked separately.

## Dependency audit snapshot

On 2026-09-23, `pnpm audit --prod --audit-level high` failed with two high and one moderate finding. The high findings are transitive Prisma dependencies: [deepmerge-ts recursive merge exhaustion](https://github.com/advisories/GHSA-ggr8-5vv4-36mx) (installed 7.1.5; patched 8.0.0) and [mysql2 authentication downgrade](https://github.com/advisories/GHSA-3f6p-5ww8-9rcr) (installed 3.15.3; patched 3.22.0). Application use of PostgreSQL does not itself establish that every dependency finding is unreachable.

US-027 must capture the complete audit report, assess reachability, select compatible upgrades and rerun migration, integration and build checks. No transitive major-version override or risk acceptance has been made. The current quality workflow does not enforce a dependency audit; passing it does not clear NFR-002. Recheck the registry at release time because advisory data changes.
