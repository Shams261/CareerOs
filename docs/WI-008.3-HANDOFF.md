# WI-008.3 handoff — post-launch polish

Branch `feat/wi-008-3-post-launch-polish` on `main` after PR #11 and the calendar-callback fix. Source: the production acceptance pass of 2026-10-21 on https://usesilsila.me (every page and flow exercised as the owner at desktop and 375 px widths; Google Calendar both directions; scheduler reminders; push enabled on the owner's devices).

## 1. Outcome

Eleven low-severity findings from the acceptance pass are fixed. No schema change, no migration, no new feature. The feature freeze stands; the next step is still daily use.

## 2. Changes

| Finding                                                         | Change                                                                                                                                                                                                                                                                |
| --------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Calendar "Choose … for tomorrow" used the viewed week's Monday  | `src/app/calendar/page.tsx` passes today to `GenerateForm`, so the hint and the default starting date are today.                                                                                                                                                      |
| Validation errors showed raw schema keys (`confidenceAfter: …`) | `issueMessages()` in `src/lib/validation.ts` names the field in words ("Confidence after: …") and skips the prefix when the message already starts with it. Used by the schedule, DSA, learning and jobs actions. Unit-tested in `tests/validation-messages.test.ts`. |
| Create forms kept their values after a save                     | DSA topic, learning subject and learning topic forms pass `resetOnSuccess` when creating, matching the other forms.                                                                                                                                                   |
| "1 attempts", "1 priorities"                                    | Pluralised on the DSA problem page and the past-reviews list.                                                                                                                                                                                                         |
| Actual sessions listed in creation order                        | Sessions are loaded ordered by `startedAt` on Today and in the schedule service.                                                                                                                                                                                      |
| Start offered on future days                                    | `ExecutionControls` takes `canStart`; Today passes `day <= today`. Stop stays available for a running session.                                                                                                                                                        |
| A 50-second session read "0h 0m"                                | A finished session under a minute reads "under a minute". Totals are unchanged.                                                                                                                                                                                       |
| Reminder preference saved silently                              | Settings uses `ActionForm` with `reminderAction`, which reports "Preference saved." or the validation problem.                                                                                                                                                        |
| Routine did not back-fill an already generated day              | Explained in the routine section copy; behaviour unchanged by design (explicit propagation, ADR-002).                                                                                                                                                                 |
| Learn reminder copy said "no closed-app push"                   | Copy corrected: inbox reminders are delivered to any device with push enabled.                                                                                                                                                                                        |
| Add-problem topic select ignored the current topic              | Not reproducible on re-check; the select already defaults to the current topic. No change.                                                                                                                                                                            |
